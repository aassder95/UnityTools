# Reward ad QA simulator

Independent package, no real ad SDK, UniTask, global clock, singleton or automatic scene searches. `TryConfigure(new RewardAdOptions(...))`, `TryLoad(placement)`, `TryShow(placement)`, `Advance(unscaledDeltaSec)` and `TryCancel(placement)` model deterministic success, load delay, no fill, network error, early skip, show failure and cancellation. Advance only once per owner tick. A loaded ad is consumed after any show result; loading and showing cannot overlap for the same placement, and only one placement can show globally per simulator.

Inject an instance into your game's ad adapter. Subscribe/unsubscribe OnChanged and grant reward only for a transition notification with Result=Completed; polling a sticky snapshot repeatedly must not repeatedly grant reward. TryGetSnapshot is read-only diagnostic state. A load success does not auto-show. Dispose releases state/subscribers; calls afterward fail. Configure rejects invalid durations/outcomes and changes while operations are active. Cancellation is explicit; call it from your owner's CancellationToken/lifecycle integration. No probability/random scheduling is used: outcomes are selected for reproducible QA.

Tools > UnityTools > QA > Reward Ad Lab provides a standalone Editor control panel with selected outcomes, manual/automatic time advancement, load/show/cancel and current state. The lab does not hook a game's service automatically. QA builds may use the pure runtime simulator through their own UI; shipping builds should choose the production SDK implementation explicitly. Existing scenes/assets are unchanged.
